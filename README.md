# library-loans-api

Учёт выдачи книг в библиотеке. Python + FastAPI, подключение к MongoDB через `motor` (асинхронный драйвер).

### Структура
```
├── app/
│   └── main.py
├── requirements.txt
└── .env.example
```

## API методы

### Проверка состояния
```bash
curl http://127.0.0.1:8050/health
```

### Создать запись о выдаче
```bash
curl -X POST http://127.0.0.1:8050/api/v1/loans \
  -H 'Content-Type: application/json' \
  -d '{"reader_name":"Марина","book_title":"Мастер и Маргарита","returned":false}'
```

### Получить список (с фильтрами)
```bash
curl http://127.0.0.1:8050/api/v1/loans
curl "http://127.0.0.1:8050/api/v1/loans?returned=false"
```

### Получить по ID
```bash
curl http://127.0.0.1:8050/api/v1/loans/<id>
```

### Обновить (частично)
```bash
curl -X PATCH http://127.0.0.1:8050/api/v1/loans/<id> \
  -H 'Content-Type: application/json' \
  -d '{"returned":true}'
```

### Удалить
```bash
curl -X DELETE http://127.0.0.1:8050/api/v1/loans/<id>
```

## Задача: Докеризация (без Docker Compose)

MongoDB уже установлен и запущен локально на машине (слушает `127.0.0.1:27017`) — его не нужно докеризировать, трогать `docker-compose.yml` здесь вообще не нужно, это чисто Docker-задача.

Этапы решения:
1. Написание `Dockerfile` (базовый образ Python, установка зависимостей, запуск через `uvicorn app.main:app --host 0.0.0.0 --port <порт>`).
2. Создание образа (`docker build`).
3. Запуск контейнера (`docker run`).
4. Проверка (`docker ps`, затем `curl` по эндпоинтам выше).

Главная сложность этой задачи — не Dockerfile (он такой же, как раньше), а то, что MongoDB крутится **на хосте**, а не в контейнере. По умолчанию контейнер находится в своей изолированной сети и `127.0.0.1` внутри контейнера — это сам контейнер, а не хост-машина.

Подумай и проверь на практике:
- Как контейнеру достучаться до MongoDB, которая слушает `127.0.0.1:27017` на хосте? Есть несколько вариантов (особый флаг сети у `docker run`, специальное DNS-имя, добавление записи в `/etc/hosts` контейнера) — поищи, какие у тебя есть варианты, и попробуй тот, что подходит под твою версию Docker/окружение.
- Не забудь передать нужные переменные окружения в контейнер при `docker run` (посмотри на флаг `-e` или `--env-file`).
- Пробрось порт приложения наружу, чтобы `curl` с хоста до него доставал.

Проверь все пять эндпоинтов и убедись, что данные реально долетают до MongoDB на хосте.
